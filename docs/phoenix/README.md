# Phoenix — UX/UI handoff

Этот каталог содержит согласованный продуктовый и визуальный контекст для
следующего этапа развития фестивального web/PWA.

Дата handoff: 28 июля 2026 года.

## С чего начинать

1. Прочитать
   [`requirements/ostrov-kak-partitura-mvp-spec-v3.md`](requirements/ostrov-kak-partitura-mvp-spec-v3.md).
   Это единый источник истины версии 3.15 для mobile и desktop.
2. Сверить существующую реализацию с
   [`IMPLEMENTATION-GAP.md`](IMPLEMENTATION-GAP.md).
3. Просмотреть desktop-макеты в порядке 33 → 41.
4. Перед изменением поведения найти соответствующий `MVP-*` и критерий
   `MVP-AC-*` в ТЗ.
5. При изменении решения одновременно обновить ТЗ, макет, матрицу соответствия
   и реестр расхождений в самом ТЗ.

## Иерархия источников

При противоречии источники имеют следующий приоритет:

1. ТЗ MVP 3.15.
2. Актуальные макеты 33–41.
3. Этот handoff и implementation-gap.
4. Текущая реализация приложения.
5. Исходные референсы и исторические макеты.

Макет иллюстрирует состояние, но не отменяет требования, которое не удалось
показать на одном холсте. Демонстрационные названия событий и маршруты в
макетах не заменяют данные статического конфига.

## Главное продуктовое решение

Mobile и desktop используют одну бизнес-логику, но разную композицию.

- Mobile: три раздела в нижней навигации — Программа, Карта, Мой маршрут.
- Desktop: одна рабочая страница с партитурой `площадка × время`, Картой и
  постоянным route dock.
- Фильтры, дата, выбранное время и выбранные сущности являются общим состоянием
  Программы и общей Карты.
- Маршруты двух фестивальных дней хранятся независимо.
- Геолокация, внешние карты, backend расписания, Share и ручной reorder не
  входят в согласованный MVP.

Полная таблица различий находится в разделе 4.1 ТЗ.

## Зафиксированные desktop-взаимодействия

### Таймлайн

- клик по шкале, drag playhead и клавиши меняют время с шагом 5 минут;
- ручное изменение устанавливает `timeAnchor=manual`;
- «Сейчас» возвращает `timeAnchor=now`;
- события открываются кликом/клавиатурой, но не перетаскиваются;
- full desktop показывает весь день без zoom;
- compact desktop использует горизонтальный pan со sticky-колонкой площадок.

### Событие

1. Клик блока открывает inspector.
2. `Подробнее` временно заменяет Карту drawer шириной 520–600 px.
3. Добавление возможно из inspector, detail или быстрого `+` в add-mode.
4. Добавление не переводит пользователя в Мой маршрут.

### Мой маршрут

- отдельного режима и кнопки `Изменить` нет;
- порядок автоматический, по времени;
- карточка имеет меню `Открыть событие / Убрать из маршрута`;
- dock имеет один контрол раскрытия/сворачивания;
- CTA пустого dock `Добавить событие` включает add-mode на той же странице;
- карта рисует только последовательные PreparedRoute, без геолокации.

### Компоновка

- default: партитура и Карта рядом;
- `Развернуть карту`: большая Карта сверху, компактная партитура снизу;
- `Вернуть рядом`: восстановление default без сброса состояния;
- layout не меняется автоматически.

## Что отсутствует в этом архиве

ТЗ перечисляет исторические mobile-макеты 07–26 и отдельный документ
`ostrov-kak-partitura-static-config-contract-v1.md`. Их бинарные/отдельные
файлы не были доступны в рабочем контексте при публикации ветки. Требования,
модель данных, static-config правила и критерии приёмки из них не потеряны:
актуальная редакция включена в единое ТЗ 3.15.

Если оригиналы будут найдены, их следует добавить без замены ТЗ:

- исторические изображения — в `docs/phoenix/mockups/mobile-history/`;
- отдельный контракт — в `docs/phoenix/requirements/`;
- затем обновить этот README и `MANIFEST.md`.

## Правило продолжения

создать новый файл и отметить старый как исторический в матрице ТЗ.
